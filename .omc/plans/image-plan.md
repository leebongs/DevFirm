## 0. 제약 — 이미지가 지켜야 하는 것

이미 통과시킨 게이트를 이미지가 깨뜨리면 안 된다. 아래는 협상 대상이 아니다.

| 기준 | 제약 | 설계 대응 |
|---|---|---|
| **A7** LCP < 2.5s | 히어로 LCP 는 **텍스트**여야 한다(§5.1) | 히어로 일러스트는 텍스트 **오른쪽**에 두고 `lg` 미만에서 숨긴다. 뷰포트 상단을 덮는 배경 이미지 금지 |
| **A7** Perf ≥ 95 | 총 바이트 증가 최소 | SVG 우선. 개별 파일 **≤ 20KB**, 래스터가 필요한 경우만 PNG |
| **A1/CLS** | 레이아웃 이동 0 | 모든 이미지에 `width`/`height` 명시. SVG 는 `viewBox` 필수 |
| **A5** axe | 위반 0 | 의미 있는 이미지는 `alt` 서술, 장식은 `alt=""` + `aria-hidden` |
| **A10** | 한국어 문장은 `content/` 에만 | **SVG 내부에 한국어 텍스트를 넣지 않는다.** 라벨이 필요한 다이어그램은 SVG 를 뼈대로만 쓰고 텍스트는 HTML 로 얹는다 |
| **§4.1** 디자인 | 다색 그라데이션·이모지 금지, 저채도 | 아래 팔레트 고정 |

### 팔레트 (사이트 토큰과 동일, 하드코딩 금지 대상 아님 — SVG 는 정적 자산이라 hex 사용)

| 역할 | hex | 용도 |
|---|---|---|
| Firm Navy | `#162e50` | 주요 면·굵은 형태 |
| Signal Blue | `#005ebd` | 강조 요소·연결선 |
| Circuit Cyan | `#00bbcb` | 액센트 **면적 5% 이하** |
| Ink | `#0f1926` | 윤곽·텍스트 대체 형태 |
| Mist | `#f3f5f8` | 배경 면 |
| Line | `#d7dbe0` | 보조 선 |
| Paper | `#ffffff` | 여백 |

### 스타일 규정 — "기하학적 플랫 일러스트"

- 평면 색면 + 얇은 선. 사실적 명암·질감 없음
- 원근 없음(정면 또는 아이소메트릭 중 **아이소메트릭으로 통일**)
- 인물은 **얼굴 없는 실루엣**(개별 인종·성별 특정 회피, 톤 통일 용이)
- 선 굵기 2단계만: 굵은 선 3px, 얇은 선 1.5px (viewBox 기준)
- 모서리 반경 2~4 (사이트 radius 10px 감각과 일치)
- **금지**: 그림자, 다색 그라데이션, 손그림 질감, 이모지, 클립아트 느낌

### 렌더 방식

정적 SVG 는 `next/image` 를 거치지 않는다. 최적화할 것이 없고, SVG 를 통과시키려면
`dangerouslyAllowSVG` 를 켜야 하는데 그건 신뢰할 수 없는 SVG 를 위한 스위치다.
자체 제작 자산이므로 `<img>` 로 직접 쓰되 **치수를 반드시 명시**한다(CLS 0).

이를 위한 전용 컴포넌트를 하나 둔다:

```
components/content/illustration.tsx   — width/height/alt 를 강제하는 얇은 래퍼
```

### PNG 파생

SVG 를 못 쓰는 경로에만 만든다. `scripts/generate-icons.mjs` 와 같은 Playwright
렌더 경로를 재사용한다(`scripts/generate-images.mjs`).

| 대상 | 이유 |
|---|---|
| `og-*.png` | OG 카드는 SVG 미지원 (완료) |
| `map-office.png` | 카카오맵 링크 미리보기·인쇄 대비 |
| P1 6종 `.png` | 외부 문서·제안서 재사용 대비 (2x, 960×720) |

## 3. 생성 순서 (codex 오케스트레이션)

의존 없는 묶음끼리 **동시** 실행한다. 한 배치 안에서는 스타일 일관성이 중요하므로
동일한 스타일 규정 블록을 프롬프트에 그대로 반복해 넣는다.

```
배치 A (동시 3): P0-1 · P0-2 · P0-3     구조 다이어그램
배치 B (동시 4): P0-4 · P0-5 · P0-6 · P0-7  시설 + 약도
배치 C (동시 6): P1-1 ~ P1-6            산업 6종  ← 세트 일관성 최우선
배치 D (동시 4): P2-1 ~ P2-4            개념 히어로
배치 E (동시 6): P3-1 ~ P3-6            소형 카드
```

각 배치 완료 후 **렌더 검수**: Playwright 로 전부 한 장에 모아 스크린샷 → 눈으로 확인 →
톤이 어긋난 것만 재생성.

## 4. 검수 기준

생성물이 아래를 만족해야 채택한다.

- [ ] viewBox 있음, 고정 width/height 속성 없음(반응형 제어는 CSS 로)
- [ ] 파일 크기 ≤ 20KB
- [ ] 팔레트 밖 색상 없음 (시안 면적 ≤ 5%)
- [ ] SVG 내부에 한국어 텍스트 없음
- [ ] `<script>`, 외부 `<image href>`, 폰트 참조 없음
- [ ] 6종 세트(P1)는 나란히 놓았을 때 형식이 동일
- [ ] 흰 배경과 `--muted` 배경 양쪽에서 형태가 살아남음

### 재작업의 원인 — 프롬프트 한 단어

1차에서 5개가 반려됐다. 원인은 **"silhouette"** 한 단어였다.
잘 나온 파일들(`cards`, `agents`, `model-backoffice`)은 원형 머리 + 사다리꼴 몸통으로
그렸지만, 실패한 파일들은 **가는 다리 위의 아치/기둥**을 그렸다. 같은 지시에서
두 갈래 해석이 나온 것이다.

수정은 형태를 좌표 수준으로 못 박는 것이었다:

> 머리 = 반지름 r 원 / 몸통 = 폭 2.2r, 높이 2.6r, 상단 모서리만 반경 r,
> 하단은 평평하게 지면에 접함 / 다리 없음 / 전체 높이 4r

**교훈**: 생성 지시에서 명사(silhouette, diagram, container)는 형태를 결정하지
못한다. `model-cic` 이 "법인을 나타내는 큰 사각형"을 **모니터와 받침대**로 그린 것도
같은 문제다. 재현이 필요한 형태는 치수·구성으로 기술해야 한다.

### 세트 단위 호출이 만든 차이

파일 1개당 1호출이 아니라 **세트 단위로 묶어** 호출했다. 산업 6종은 한 번의
호출로 생성해 시안 감지 프레임의 위치·형태, 지면 다이아몬드, 네이비 질량이
6장 모두 일치한다. 개별 호출이었다면 맞출 수 없었을 부분이다.

## 6. 글래스모피즘 + 사진 (2026-07-30)

요청: 회사소개·솔루션에 사진, 개념 도형으로 설명, 홈 배경에 소프트웨어 기업
이미지, Glassmorphic 프론트엔드. 적용 범위는 **홈 + 헤더**로 합의(사용자 선택).

### 계획서와의 충돌 — 명시하고 진행

§4.1 "조용한 정밀함"은 *그림자 최소·다색 그라데이션 금지*를 명시한다.
Glassmorphism 은 그 반대편 언어이고 **A6(색 대비)·A7(LCP)** 를 정면으로 위협한다.
요청대로 구현하되 두 게이트를 지키는 방식을 택했다. 결과적으로 둘 다 유지했다.

### 핵심 판단 — 흰 유리를 버렸다

`rgba(255,255,255,.1)` 은 글래스모피즘의 관용 표현이지만 **사진 위에서는 실패한다.**
배경을 밝게 끌어올려 흰 텍스트와 경쟁하기 때문이다. 실측:

| 스크림 | 흰 유리 0.14 | 흰 유리 0.10 |
|---|---|---|
| 0.82 | 6.64:1 ✖ | 7.49:1 |
| 0.90 | 8.56:1 | 9.78:1 |

7:1 을 맞추려면 스크림 0.90 이 필요했고, 그 시점에 사진은 10%만 비쳐
**배경을 깐 의미가 사라졌다.**

→ 유리 틴트를 **어두운 네이비**로 뒤집었다. 유리면 스스로 어두움을 보장하므로
뒤에 어떤 사진이 와도 대비가 계산 가능하고, 스크림을 옅게 깔아 사진을 살릴 수 있다.

**대가**: 대비를 지키는 유리는 꽤 불투명해진다(0.82). 투명도가 아니라
blur · 밝은 테두리 · 상단 광원이 유리 질감을 만든다.

### 토큰 (app/globals.css)

이름을 "강함/약함"이 아니라 **텍스트를 얹는가**로 나눴다. 그것이 실제 제약이다.

| 토큰 | 값 | 용도 | 최악 조건 대비 |
|---|---|---|---|
| `--glass-fill` | navy / 0.82 | 글자가 올라가는 면 | 본문 10.14:1 · 시안 4.59:1 |
| `--glass-fill-subtle` | navy / 0.55 | 장식 전용(텍스트 금지) | 게이트 비대상 |
| `--scrim-text` | navy / 0.88 | 헤드라인이 앉는 쪽 | 13.23:1 |
| `--scrim-photo` | navy / 0.42 | 사진을 보여줄 쪽 | 텍스트 없음 |

클래스: `.glass` `.glass-subtle` `.glass-sheen` `.hero-scrim`
폴백: `@supports not (backdrop-filter)` → 불투명 면 /
`prefers-reduced-transparency: reduce` → 유리 해제

### 대비 검사기 확장이 설계를 이끌었다

유리면은 단일 색이 아니라 [사진]→[스크림]→[유리]가 겹친 결과다. 쌍 비교로는
계산이 안 되므로 `stackOn()` 으로 레이어를 **순백 사진(최악)** 위에 합성하게 했다.
첫 시도에서 두 건이 즉시 걸렸고(약한 유리 6.6:1, 시안 3.6:1) 그 수치가 위 결론을
만들었다. 검사기가 없었다면 눈으로는 괜찮은 채로 배포됐다.

덤으로 `:root` 파서가 **첫 블록만 읽어** 새 토큰을 통째로 놓치던 버그가 드러났다.
검사기가 검사 대상을 못 보는 상태였으므로 파서를 고쳤다(모든 `:root` 순회).

### 히어로를 헤더 아래로 밀어야 헤더 유리가 작동한다

sticky 헤더는 히어로 **위쪽**에 있어 블러할 대상이 없다. 첫 렌더에서 헤더가
그냥 흰 막대로 보인 이유다. 음수 마진으로 사진을 헤더 뒤까지 끌어올리고
같은 크기의 패딩으로 콘텐츠 위치를 되돌렸다.

```
-mt-16 pt-16 lg:-mt-18 lg:pt-18
```

또한 히어로 스크림의 가로 램프를 넓게(14%→78%) 잡았다. 좁으면 사진 안의
벽·기둥 모서리와 겹쳐 그라데이션이 아니라 **이음매**처럼 보인다.

### 사진

higgsfield `nano_banana_2` (Nano Banana Pro) 로 6장 생성.
공통 프롬프트 조건: 저채도 네이비 그레이드 · 깊은 그림자 · **텍스트·로고 없음** ·
다큐멘터리 톤(스톡 사진 느낌 배제). 히어로는 **좌측 1/3 을 비우도록** 지시해
헤드라인 자리를 확보했다.

| 파일 | 용도 | AVIF |
|---|---|---|
| `hero-office` | 홈 전면 배경 (2400×1018) | 30KB |
| `about-team` · `about-space` · `about-backoffice` | 회사소개·홈 | 33·29·41KB |
| `solutions-industrial` · `solutions-desk` | 솔루션 | 30·19KB |

**원본은 장당 5~7MB PNG(합 35.2MB).** 그대로 커밋하면 성능 작업이 무의미해진다.
`scripts/optimize-photos.mjs` 가 리사이즈 + AVIF/WebP 로 **35.2MB → 0.4MB**.
원본은 `assets/photo-src/`(gitignore) — 스크립트로 재생성 가능.

`components/content/photo.tsx` 는 `next/image` 대신 `<picture>` 를 쓴다.
변환본이 이미 있으므로 요청 시점에 최적화할 것이 없다.

**알려진 흠 2건**: `about-backoffice` 배경에 인물 얼굴이 약간, `solutions-desk`
대시보드에 팔레트 밖 녹색. 계획 O-2 가 처방한 저채도 네이비 오버레이(`tone` prop)로
눌렀다 — 오버레이가 톤 통일과 팔레트 이탈 억제를 동시에 한다.
