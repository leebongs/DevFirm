## 0. 제약 — 이미지가 지켜야 하는 것

이미 통과시킨 게이트를 이미지가 깨뜨리면 안 된다. 아래는 협상 대상이 아니다.

| 기준 | 제약 | 설계 대응 |
|---|---|---|
| **A7** LCP < 2.5s | 히어로 LCP 는 **텍스트**여야 한다(§5.1) | 히어로 일러스트는 텍스트 **오른쪽**에 두고 `lg` 미만에서 숨긴다. 뷰포트 상단을 덮는 배경 이미지 금지 |
| **A7** Perf ≥ 95 | 총 바이트 증가 최소 | SVG 우선. 개별 파일 **≤ 20KB**, 래스터가 필요한 경우만 PNG |
| **A1/CLS** | 레이아웃 이동 0 | 모든 이미지에 `width`/`height` 명시. SVG 는 `viewBox` 필수 |
| **A5** axe | 위반 0 | 의미 있는 이미지는 `alt` 서술, 장식은 `alt=""` + `aria-hidden` |
| **A10** | 한국어 문장은 `content/` 에만 | **SVG 내부에 한국어 텍스트를 넣지 않는다.** 라벨이 필요한 다이어그램은 SVG 를 뼈대로만 쓰고 텍스트는 HTML 로 얹는다 |
| **§4.1** 디자인 | 다색 그라데이션·이모지 금지, 저채도 | 아래 팔레트 고정 |

### 팔레트 (사이트 토큰과 동일, 하드코딩 금지 대상 아님 — SVG 는 정적 자산이라 hex 사용)

| 역할 | hex | 용도 |
|---|---|---|
| Firm Navy | `#162e50` | 주요 면·굵은 형태 |
| Signal Blue | `#005ebd` | 강조 요소·연결선 |
| Circuit Cyan | `#00bbcb` | 액센트 **면적 5% 이하** |
| Ink | `#0f1926` | 윤곽·텍스트 대체 형태 |
| Mist | `#f3f5f8` | 배경 면 |
| Line | `#d7dbe0` | 보조 선 |
| Paper | `#ffffff` | 여백 |

### 스타일 규정 — "기하학적 플랫 일러스트"

- 평면 색면 + 얇은 선. 사실적 명암·질감 없음
- 원근 없음(정면 또는 아이소메트릭 중 **아이소메트릭으로 통일**)
- 인물은 **얼굴 없는 실루엣**(개별 인종·성별 특정 회피, 톤 통일 용이)
- 선 굵기 2단계만: 굵은 선 3px, 얇은 선 1.5px (viewBox 기준)
- 모서리 반경 2~4 (사이트 radius 10px 감각과 일치)
- **금지**: 그림자, 다색 그라데이션, 손그림 질감, 이모지, 클립아트 느낌

## 2. 배치 규칙

### 디렉터리

```
public/images/
├─ model/      P0-1~3   구조 다이어그램
├─ workspace/  P0-4~6   시설
├─ map/        P0-7     약도
├─ agents/     P1       산업 6종
├─ hero/       P2       개념 히어로
└─ cards/      P3       소형
```

### 렌더 방식

정적 SVG 는 `next/image` 를 거치지 않는다. 최적화할 것이 없고, SVG 를 통과시키려면
`dangerouslyAllowSVG` 를 켜야 하는데 그건 신뢰할 수 없는 SVG 를 위한 스위치다.
자체 제작 자산이므로 `<img>` 로 직접 쓰되 **치수를 반드시 명시**한다(CLS 0).

이를 위한 전용 컴포넌트를 하나 둔다:

```
components/content/illustration.tsx   — width/height/alt 를 강제하는 얇은 래퍼
```

### PNG 파생

SVG 를 못 쓰는 경로에만 만든다. `scripts/generate-icons.mjs` 와 같은 Playwright
렌더 경로를 재사용한다(`scripts/generate-images.mjs`).

| 대상 | 이유 |
|---|---|
| `og-*.png` | OG 카드는 SVG 미지원 (완료) |
| `map-office.png` | 카카오맵 링크 미리보기·인쇄 대비 |
| P1 6종 `.png` | 외부 문서·제안서 재사용 대비 (2x, 960×720) |

## 3. 생성 순서 (codex 오케스트레이션)

의존 없는 묶음끼리 **동시** 실행한다. 한 배치 안에서는 스타일 일관성이 중요하므로
동일한 스타일 규정 블록을 프롬프트에 그대로 반복해 넣는다.

```
배치 A (동시 3): P0-1 · P0-2 · P0-3     구조 다이어그램
배치 B (동시 4): P0-4 · P0-5 · P0-6 · P0-7  시설 + 약도
배치 C (동시 6): P1-1 ~ P1-6            산업 6종  ← 세트 일관성 최우선
배치 D (동시 4): P2-1 ~ P2-4            개념 히어로
배치 E (동시 6): P3-1 ~ P3-6            소형 카드
```

각 배치 완료 후 **렌더 검수**: Playwright 로 전부 한 장에 모아 스크린샷 → 눈으로 확인 →
톤이 어긋난 것만 재생성.

## 4. 검수 기준

생성물이 아래를 만족해야 채택한다.

- [ ] viewBox 있음, 고정 width/height 속성 없음(반응형 제어는 CSS 로)
- [ ] 파일 크기 ≤ 20KB
- [ ] 팔레트 밖 색상 없음 (시안 면적 ≤ 5%)
- [ ] SVG 내부에 한국어 텍스트 없음
- [ ] `<script>`, 외부 `<image href>`, 폰트 참조 없음
- [ ] 6종 세트(P1)는 나란히 놓았을 때 형식이 동일
- [ ] 흰 배경과 `--muted` 배경 양쪽에서 형태가 살아남음

### 재작업의 원인 — 프롬프트 한 단어

1차에서 5개가 반려됐다. 원인은 **"silhouette"** 한 단어였다.
잘 나온 파일들(`cards`, `agents`, `model-backoffice`)은 원형 머리 + 사다리꼴 몸통으로
그렸지만, 실패한 파일들은 **가는 다리 위의 아치/기둥**을 그렸다. 같은 지시에서
두 갈래 해석이 나온 것이다.

수정은 형태를 좌표 수준으로 못 박는 것이었다:

> 머리 = 반지름 r 원 / 몸통 = 폭 2.2r, 높이 2.6r, 상단 모서리만 반경 r,
> 하단은 평평하게 지면에 접함 / 다리 없음 / 전체 높이 4r

**교훈**: 생성 지시에서 명사(silhouette, diagram, container)는 형태를 결정하지
못한다. `model-cic` 이 "법인을 나타내는 큰 사각형"을 **모니터와 받침대**로 그린 것도
같은 문제다. 재현이 필요한 형태는 치수·구성으로 기술해야 한다.

### 세트 단위 호출이 만든 차이

파일 1개당 1호출이 아니라 **세트 단위로 묶어** 호출했다. 산업 6종은 한 번의
호출로 생성해 시안 감지 프레임의 위치·형태, 지면 다이아몬드, 네이비 질량이
6장 모두 일치한다. 개별 호출이었다면 맞출 수 없었을 부분이다.
